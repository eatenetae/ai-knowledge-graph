# AI PM 六大能力域

> 机器可读的登记表在 [`schema/pm-domains.json`](../schema/pm-domains.json)（构建期按它校验，
> 案例的 `domains` 字段引用它的 id）。这份文档是「为什么是这六个、怎么用它」的完整定义。

## 这套框架解决什么问题

v1 的知识图谱面向「学 AI 的人」，55 个节点是一张工程视角的依赖图。但 AI 产品经理
面对的问题不是「学会实现它」，而是「判断它」：这个需求该不该用 AI 做、往哪条技术路上做、
多少钱能做出来、怎么知道做得好不好、合规风险在哪、怎么从 demo 走到上线。

六大能力域就是把这六类判断拆开。它有三个用途：

1. **给知识节点标注 PM 相关性**（`pm: core / useful`），生成「必修地图」——PM 面试前
   必须掌握的节点子集，而不是整张 55 节点的图。
2. **给案例分类**：每个案例 frontmatter 的 `domains` 挂 1-6 个能力域，说明它练的是哪几块判断力。
3. **给面试题分组导航**：题库按场景分组，但每道题的复习节点都能沿 `pm` 标记找到自己的位置。

## 六个域

| # | id | 能力域 | 一句话 | 典型判断 |
|---|---|---|---|---|
| 1 | `capability-boundaries` | 能力边界判断 | AI 能做什么 / 不能做什么，幻觉与不确定性从哪来 | 「这个需求模型现在真的做得到吗，还是我们想多了？」 |
| 2 | `solution-intuition` | 技术方案理解 | RAG / 微调 / 提示工程 / Agent 的选型直觉 | 「知识更新频繁 → RAG；行为风格固定 → 微调；都不沾 → 先改提示词」 |
| 3 | `cost-performance` | 成本与性能 | token 计费、延迟、缓存与量化的产品影响 | 「按席位定价但按 token 付费，毛利模型算得过来吗？」 |
| 4 | `evaluation-quality` | 评测与质量 | 怎么定义「好」、评测集、回归 | 「上线前拿什么说服自己（和老板）它能用？」 |
| 5 | `data-compliance` | 数据与合规 | 数据飞轮、隐私、内容安全、提示注入 | 「用户数据能进模型吗？谁对生成的内容负责？」 |
| 6 | `delivery` | 落地方法 | POC 到上线、灰度、人机协同、失败兜底 | 「demo 很惊艳，上了量会变成什么样？兜底方案是什么？」 |

选型说明：这六个不是学院派的学科划分，而是从「AI PM 在真实工作里被问到的决策」倒推的——
每个域都对应一类**躲不掉的判断**。边界判断放在第一位，因为它是其余五项的地基：
不知道模型做不到什么，后面每一项都会高估。

## `pm` 标注怎么打（core / useful / 不标）

节点 frontmatter 的可选字段 `pm`：

- **`core`** —— AI PM 面试前**必须掌握**。判断标准：面试官问到时答不出，会直接减分；
  且掌握它不需要写代码。约束：**宁缺毋滥**（验收区间 25-35 个，见登记表的
  `core_count_bounds`），并且每个 core 节点必须登记进某个能力域的 `core_nodes`。
- **`useful`** —— PM 相关、值得看，但不知道也能过面试。多为「理解了更好、不理解不致命」
  的机制细节（KV Cache、LoRA、重排序）。
- **不标** —— 偏工程深度的内容（损失函数、位置编码、编码器-解码器），PM 不需要。

打标的流程约束（构建期全部强制校验，见下）：core 集合必须覆盖全部六大能力域；
每个 core 节点都能沿前置依赖边回溯到基础节点——「必修」的内容不能悬空。

## 构建期校验（改这里之前先读）

`schema/pm-domains.json` 不是普通文档，构建会校验它的内部一致性，改错构建就红：

| 校验 | 保证什么 |
|---|---|
| `core_nodes` 引用的节点必须存在 | 登记表不悬空 |
| `core_nodes` 里的节点必须真的标了 `pm: core` | 登记表与 frontmatter 不漂移（写反了同样报错） |
| 标了 `pm: core` 的节点必须出现在恰好一个能力域 | 必修地图不缺项、不重复归域 |
| 每个能力域至少一个 core 节点 | 六域全覆盖 |
| core 总数在 `core_count_bounds` 区间内 | 「宁缺毋滥」有硬约束 |
| 每个 core 节点沿前置边能回溯到无前置的基础节点 | 必修内容的学习链有头 |
| 案例 `domains` 引用的能力域必须已登记 | 案例分类不悬空 |

## 维护

- 新增节点时顺手判断要不要标 `pm`。标 `core` 的动作是「同时改两处」：节点 frontmatter
  和 `schema/pm-domains.json` 的 `core_nodes`——构建会拦住只改一处的情况。
- 六个域的增删是**产品决策**（影响首页必修地图的结构），不要在内容 PR 里顺手做；
  先开 issue 讨论。
- 案例至少挂 1 个能力域；一道面试题通过 `nodes` 挂靠知识节点，间接接入这套体系。
