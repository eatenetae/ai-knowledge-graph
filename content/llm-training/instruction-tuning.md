## 直觉

预训练出来的模型有个让人抓狂的毛病：**它不会回答问题，它只会接着写。**

你问「法国的首都是哪里？」，它可能回你「意大利的首都是哪里？德国的首都是哪里？」——因为在它读过的网页里，这种问句经常成排出现。它没有做错，它只是在做它唯一被训练过的事：猜下一个词。

指令微调（instruction tuning）解决的就是这件事：**拿几万到几百万条「指令 + 理想回答」的样本，再训一轮。** 样本长这样：

```
指令：把下面这句话翻译成英文：今天天气很好
回答：The weather is nice today.
```

训完之后，同一个模型，同样的参数规模，**突然就会「听人话」了**。这个转变在 2021-2022 年被发现时相当震撼——需要的样本量比预训练小了好几个数量级（预训练几万亿词，指令微调常常只要几万条），却能带来质变。

一个类比：**一个博览群书但没上过班的实习生，经过一周岗前培训**。书还是那些书（知识没变），但从此知道「老板问一句，我要答一句」，而不是继续背目录。**指令微调教的是行为，不是知识。**

## 细节

**关键机制**

- **数据长什么样**：主流做法是把各种 NLP 任务**统一改写成自然语言指令**。分类写成「判断情感：…」、摘要写成「用一句话概括：…」、翻译写成「译成英文：…」。这一步叫**任务模板化**，FLAN 论文的核心贡献就是证明了「任务种类够多」比「单一任务数据够多」更有效。
- **和预训练的本质区别**：
  - 预训练：损失只算在**回答部分**吗？不——预训练对整段文本都算损失，因为它在学语言本身。
  - 指令微调：损失**只算在回答部分**。指令本身不产生损失，模型不需要学会「生成指令」，只需要学会「看到指令后该产出什么」。
  - 这个细节很关键：如果对指令也算损失，模型会倾向于模仿用户的提问方式，而不是回答问题。
- **规模效应**：指令微调的有效性依赖底座模型足够大。小模型做指令微调，往往只是学会了指令的**格式**，没学会背后的**能力**——这叫「指令微调主要教会模型已经会的东西怎么用」。
- **数据质量 > 数量**：LIMA 等工作表明，一千条精心撰写的样本能逼近几万条噪声样本的效果。这也是为什么「数据配方」成了各家模型的核心机密之一。
- **在训练流水线里的位置**：
  ```
  预训练（学知识）→ 指令微调 / SFT（学听话）→ 偏好对齐 / RLHF（学讨人喜欢且安全）
  ```
  指令微调这一步也常被叫做 **SFT（Supervised Fine-Tuning，有监督微调）**——在 LLM 语境里这两个词基本同义。

**和提示工程的关系**

指令微调是**提示工程有效的前提**。一个没做过指令微调的基座模型，你怎么写提示词效果都有限；而做过指令微调的模型，会因为「指令-回答」这个格式被反复强化，从而**对提示词的措辞异常敏感**。这就是为什么在同一个模型上改几个字，效果能差出一大截。

**可运行代码**

```python
# 指令微调的数据格式：关键是把「指令」和「回答」分开，损失只算回答
def to_chat(instruction, response):
    return {
        "prompt": f"### 指令：\n{instruction}\n\n### 回答：\n",
        "completion": response + "\n",
    }

samples = [
    to_chat("把下面这句话翻译成英文：今天天气很好", "The weather is nice today."),
    to_chat("用一句话概括：退款将在 3 个工作日内原路退回。", "退款 3 天内到账。"),
    to_chat("判断情感（正面/负面）：等了一个小时才上菜", "负面"),
]

for s in samples:
    print(repr(s["prompt"]))
    print("  →", repr(s["completion"]))
    print()

# 训练时，prompt 部分的 token 标签设为 -100（忽略），只对 completion 算损失
# 这就是 SFT 与预训练在实现上唯一实质的差别
```

真正训练时，`prompt` 段的标签会被置成 `-100`（PyTorch 交叉熵的忽略位），**只有 `completion` 参与损失计算**。这一行设置，就是「学听话」和「学续写」的分界线。
